# 品質チェックプロンプト テンプレート

> **使い方**: 変数定義表を埋めてから、本文中の `{{変数名}}` をすべて実際の値に置き換えてください。
> 置換後のファイルを `prompt/品質チェックプロンプト.md` として保存し、Quality Check Agent に読み込ませます。

---

## 変数定義

| 変数名 | 説明 | AI経営実装版での値（記入例） | あなたのプロジェクト |
|--------|------|---------------------------|-------------------|
| `{{AUTHOR_PERSONA}}` | 著者ペルソナ | BtoBコンサルティング会社の編集責任者兼、経営層向けコンテンツマーケティングの専門家 | |
| `{{TARGET_READERS}}` | 対象読者（列挙） | CEO、COO、CFO、DX担当役員、経営企画、事業部長などの経営層 | |
| `{{TARGET_READER_GROUP}}` | 対象読者の総称 | 経営層 | |
| `{{TOPIC_DOMAIN}}` | 記事テーマドメイン | AI組織実装・AI経営実装 | |
| `{{ARTICLE_GOAL}}` | 記事の最終目的 | AI組織実装・AI経営実装に関するコンサルティングサービスの相談・受注につなげること | |
| `{{CORE_PROBLEM}}` | 中心的な問題設定 | 使っているのに成果が出ない | |
| `{{STRUCTURAL_DIMENSIONS}}` | 問題の構造的側面 | 業務プロセス・KPI・責任・ガバナンスの問題 | |
| `{{READER_ACCOUNTABILITY}}` | 読者の説明責任先 | 取締役会、経営会議、投資家、株主への説明責任 | |
| `{{IMPACT_PERSPECTIVE_1}}` | 経営インパクト観点①（ポジティブ視点） | 投資判断・経営成果・組織設計・リスク・競争優位 | |
| `{{BUSINESS_FUNCTIONS}}` | 具体的業務機能の列挙 | 業務プロセス・KPI・責任・ガバナンス | |
| `{{CONSECUTIVE_TOPIC}}` | 第N回記事として次回への接続性（変数として記事構成から参照） | 第1回記事として、次回以降への接続 | |
| `{{TRUSTED_SOURCES}}` | 信頼できる情報源の例示 | BCG、PwC、JUAS、NRI、企業公式発表 | |
| `{{SCORING_ITEM_3_LABEL}}` | 評価項目3のラベル | 経営層への刺さり | |
| `{{SCORING_ITEM_3_DESC}}` | 評価項目3の説明 | CEO、COO、CFO、DX担当役員が自分ごととして読めるか | |
| `{{SCORING_ITEM_3_SUBPOINT}}` | 評価項目3のサブポイント | 取締役会、経営会議、投資家、株主への説明責任に接続できているか | |
| `{{SCORING_ITEM_9_LABEL}}` | 評価項目9のラベル | 受注導線 | |
| `{{SCORING_ITEM_9_DESC}}` | 評価項目9の説明 | 最後に自然な相談導線があるか | |
| `{{CTA_DIAGNOSIS_ITEMS}}` | 初回診断で得られる成果物 | 初回診断、現状把握、優先業務特定、KPI設計、90日アクション | |
| `{{CTA_BAD_EXAMPLE}}` | 避けるべきCTA例 | 相談してください | |
| `{{DISQUALIFIED_PATTERN_1}}` | 不合格パターン（コンテンツ面） | AIツール紹介に寄りすぎている | |
| `{{DISQUALIFIED_PATTERN_2}}` | 不合格パターン（読者面） | 経営層が読んだときに違和感を持つ | |
| `{{DISQUALIFIED_PATTERN_3}}` | 不合格パターン（受注面） | 問い合わせにつながらない | |

## プロンプト本文（変数置換後に Quality Check Agent へ渡す）

---

あなたは、{{AUTHOR_PERSONA}}です。
以下の記事について、かなり厳しく品質評価してください。
対象読者は、{{TARGET_READERS}}です。
記事の目的は、単なる情報提供ではなく、読者に「これは自社の課題だ」と感じてもらい、最終的に{{ARTICLE_GOAL}}です。

評価にあたっては、以下の観点を必ず確認してください。

【評価観点】

1. {{TARGET_READER_GROUP}}に刺さるか
   - 冒頭で{{TARGET_READER_GROUP}}の関心をつかめているか
   - {{TOPIC_DOMAIN}}の「使い方」ではなく「{{IMPACT_PERSPECTIVE_1}}」の話になっているか
   - {{TARGET_READERS}}が自分ごととして読めるか
   - {{READER_ACCOUNTABILITY}}に接続できているか

2. 問題設定は鋭いか
   - 表面的な問題ではなく「{{CORE_PROBLEM}}」という深い問題設定になっているか
   - ありきたりな{{TOPIC_DOMAIN}}論、ツール紹介、ノウハウ紹介に寄っていないか
   - 読者が「まさに自社の課題だ」と感じる具体的な痛みを突いているか
   - 抽象論ではなく、{{STRUCTURAL_DIMENSIONS}}として描けているか

3. 論旨の一貫性
   - 記事全体の中心メッセージが明確か
   - 各章が自然につながっているか
   - 途中で論点が広がりすぎていないか
   - {{CONSECUTIVE_TOPIC}}が自然か
   - 結論が冒頭の問いにきちんと回収されているか

4. 具体性
   - 事例、統計データ、調査、企業事例、実務例が適切に使われているか
   - 具体例が{{TARGET_READER_GROUP}}にとってイメージしやすいか
   - 単なる「効率化」ではなく、どの業務のどの工程が変わるのかまで踏み込めているか
   - {{BUSINESS_FUNCTIONS}}などの実務に接続できているか

5. ファクトの信頼性
   - 統計データの出典が明確か
   - 数字の定義や調査対象が混同されていないか
   - 「達成」「実現」「最多」「圧倒的」などの断定表現が過剰でないか
   - 一次情報で確認できない企業事例を断定していないか
   - {{TRUSTED_SOURCES}}などの使い方が正確か
   - 出典が弱い場合、どこを修正すべきか指摘すること

6. 独自性
   - どこにでもある{{TOPIC_DOMAIN}}記事になっていないか
   - 執筆企業ならではの診断軸、フレームワーク、方法論があるか
   - コンサルサービスにつながる独自フレームが記事の中心にあるか
   - 読者が「この会社に相談すると、自社の課題を整理してもらえそう」と感じるか

7. 読みやすさ
   - 文章量が多すぎないか
   - {{TARGET_READER_GROUP}}が短時間で要点を把握できるか
   - 図表・比較表・箇条書きが適切に入っているか
   - 表が多すぎて資料っぽくなっていないか
   - 重要な主張が埋もれていないか
   - 章タイトルだけを読んでも論旨が追えるか

8. 表現の強さと品位
   - {{TARGET_READER_GROUP}}向けとして、煽りすぎず、しかし弱すぎない表現になっているか
   - 「本当の理由」「圧倒的多数」「通用しない」などの表現が安っぽく見えないか
   - 現場を軽視するような言い方になっていないか
   - 説教調・上から目線になっていないか
   - 信頼感のある語り口になっているか

9. {{SCORING_ITEM_9_LABEL}}
   - {{SCORING_ITEM_9_DESC}}
   - 「{{CTA_BAD_EXAMPLE}}」だけでなく、相談すると何が得られるかが明確か
   - {{CTA_DIAGNOSIS_ITEMS}}など、具体的な提供価値が示されているか
   - 記事の問題提起とCTAがつながっているか
   - 営業色が強すぎず、しかし問い合わせにつながる設計になっているか

10. 修正優先度
    - どこを直せば最も品質が上がるか
    - 公開前に必ず直すべき点
    - できれば直したい点
    - 修正しなくても許容できる点
    に分けて指摘すること

【出力形式】

以下の形式で回答してください。

1. 総合評価
   - 100点満点で採点
   - 一言で結論
   - {{TARGET_READER_GROUP}}に受けるか、受注につながるかを明記

2. 評価サマリー表
   以下の観点で10点満点評価すること。
   - タイトル
   - 冒頭の掴み
   - {{SCORING_ITEM_3_LABEL}}
   - 問題設定の鋭さ
   - ビジネスインパクト
   - 独自性
   - 具体性
   - ファクト信頼性
   - 読みやすさ
   - {{SCORING_ITEM_9_LABEL}}

3. 良い点
   - 特に残すべき強い箇所を3〜5点挙げる
   - なぜ良いのかを具体的に説明する

4. 厳しく見た弱点
   - {{TARGET_READER_GROUP}}に刺さらない可能性がある箇所
   - ありきたりに見える箇所
   - 信頼性を損ねる可能性がある箇所
   - 受注・行動につながりにくい箇所
   を具体的に指摘する

5. ファクトチェック上の注意
   - 数字、調査、企業事例、出典表現で危うい箇所を指摘
   - 断定を弱めるべき箇所があれば修正案を出す

6. 文章・構成の修正案
   - 章立ての改善案
   - 削るべき箇所
   - 強調すべき箇所
   - 図表化すべき箇所
   を具体的に提案する

7. 赤入れ例
   重要な箇所について、以下の形で修正文を示す。
   【現状】
   ...
   【修正案】
   ...

8. CTA改善案
   記事の最後に入れるべき、自然で受注につながるCTA文を提案する。
   「初回診断で何を得られるか」を必ず含める。

9. 最優先修正リスト
   優先順位順に5〜10項目で整理する。
   各項目について「理由」も書く。

10. 最終判断
    - 現状で公開可能か
    - 公開するなら最低限どこを直すべきか
    - 修正後に何点まで上がるか
    を明記する。

【評価の厳しさ】

かなり厳しく見ること。
褒めるだけではなく、{{DISQUALIFIED_PATTERN_1}}箇所、{{DISQUALIFIED_PATTERN_2}}箇所、{{DISQUALIFIED_PATTERN_3}}箇所を遠慮なく指摘すること。
ただし、単なる批判ではなく、必ず実用的な修正案を示すこと。
